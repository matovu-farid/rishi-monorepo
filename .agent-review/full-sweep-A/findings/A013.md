## Bug Summary
`tutorialStore.test.ts` "should reset tour" (L47-52) only asserts two
of the five state fields that production `resetTour()` mutates
(tutorialStore.ts:137-151) AND fails to assert that the
`HINTS_SEEN_KEY` (`rishi:hints-seen`) localStorage entry is removed.
This is the same incomplete-reset-assertion anti-pattern that pilot
Q04 fixed for pdfStore `resetParagraphState`. A regression in
`resetTour()` that forgets to clear `hintsShown`, `tourActive`,
`tourStep`, or `tourPaused`, or forgets the `localStorage.removeItem(HINTS_SEEN_KEY)`
call at L147, will pass this test.

## Tester Analysis
Production `resetTour()` (tutorialStore.ts:137-151) is a 5-field reset
plus 2 persistence side-effects:

```ts
set({
  tourCompleted: false,   // L139 — only this asserted
  tourStep: 0,            // L140 — UNASSERTED
  tourPaused: false,      // L141 — UNASSERTED
  tourActive: false,      // L142 — UNASSERTED
  hintsShown: {}          // L143 — UNASSERTED
})
persistTourCompleted(false)                       // L145 — partially asserted via localStorage.getItem on L51
localStorage.removeItem(HINTS_SEEN_KEY)           // L147 — UNASSERTED
```

The test fixture pre-seeds `tourCompleted: true` (L48) but does not
seed any of the other 4 fields, so post-reset values are all default
and any incomplete reset will silently pass.

Suggested replacement: pre-seed all five fields to non-default values
(`tourActive:true, tourStep:2, tourPaused:true, tourCompleted:true,
hintsShown:{seen:true}`), pre-seed both localStorage keys, then assert
all five state fields go to default AND both localStorage keys are
gone.
