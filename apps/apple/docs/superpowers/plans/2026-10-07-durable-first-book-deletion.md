# Durable-first Book deletion

Revision 3 — PASS, 0 open Critical/High/Medium; designated independent re-review closed the R2 partial-save classification High. Addendum to delete-reimport-persistence; supersedes its requirement to drain before committing deletion. No production/test changes in this planning pass.

## Evidence and decision

The affected phone Book is The Kybalion, E9CF26D2-1724-5A03-A0FE-4E8BA3284456, generation 77. It is ready and still canonical; native reading authorization is not revoked/tombstoned and sync metadata has dirty=1,tombstone=0 after the reported minute-long wait. The typed import alert proves in-memory deletion retirement exists. Current LibraryViewModel.completeDeletion awaits beforeBookDeleted, whose factory awaits drainBookForDeletion, BEFORE persisting the tombstone. This ordering allows any idle retained reader/source owner to prevent durable deletion indefinitely. The exact remaining holder is not needed to fix this architectural dependency.

Keep genuine source/ARC drains intact. Commit durable logical deletion first; reclaim physical files after those drains. Do not replace ARC drains with effect-only drains: Readium/PDF native navigators can perform lazy file access outside the existing short effect admissions, so skipping owners would weaken the current safety contract. SwiftUI may retain idle VMs; retained references must not control whether the logical deletion is saved.

## Closed invariants

1. Before the first durable stage, synchronously fence the exact owner/generation/Book and cancel owned indexing. This produces one immutable BookDeletionRetirementWitness. Do not await reader close, recovery claims, registrations, materialization, promotion, indexing, source effects, ARC owners, native revokeBookReading, or remote work before persistence.
2. Every finite persistence stage holds original-account owner-operation admission and rechecks immutable owner/generation after suspensions. The native canonical mutation validates current account authorization in its single serialized DB turn. Never reconstruct authority using a newer generation.
3. The native Book identity gate serializes local/remote tombstone publication against live downloads/import metadata writes. A local tombstone remains permanently closed even after acknowledgement. Never call public gate-taking methods recursively inside this gate.
4. Atomic native logical deletion retains a revoked+tombstoned BookReadingAuthorizationEntity while removing canonical Book, positions/highlights/bookmarks/fingerprint/chapter rows. Preserve PendingBookMaterializationEntity for exact staging cleanup. Existing finite DB writes already entered finish before this serialized turn; later scoped writes validate Book/auth and fail. Do not await LocalMutationAdmissionBarrier drainage before this turn.
5. Native authorization cannot be re-created for the closed UUID. When no reading row exists (legacy book), create a tombstoned authorization using captured owner/generation and a fresh revision solely as a permanent deny record. It must never grant readable authority. No new schema.
6. The old cleanup acts only on captured old UUID, owner, validated pending token, managed namespace and attempt staging path. New same-file imports use fresh UUID/path. Do not delete files until real old materialization/promotion/indexing/source-effect/owner drains finish. Never timeout or force-release them.
7. Completion of logical commit clears pending UI deletion and suppresses durable tombstones across every library projection/restart. Cleanup latency or failure cannot resurrect the old Book or block reimport. Report cleanup failure via scoped log/retry; no failed-visible overlay for a successful logical commit.
8. Before tombstone persistence, failure retains the existing rollback/error behavior. After tombstone persistence, failure cannot reopen old source/native authority; retry canonical reconciliation and cleanup. Account replacement or a newer witness must not be undone by old callbacks.

## Minimal APIs and bounded file work

### A. Split fence from real drain (BookImportLifecycle.swift)

Keep retireBookForDeletion synchronous. Add waitForRetiredBookDeletion(witness:) async to execute the existing recovery/materialization/promotion/source-retirement/index/source-owner waits using the immutable witness fields WITHOUT issuing a new retirement UUID. Existing drainBookForDeletion remains compatibility wrapper: retire once, then wait. This wait returns only on real completion and does not reopen any gate. Remote deletion gets the same split using its own exact retirement witness. Live replacement APIs remain distinct.

### B. One local closed-identity mutation seam (SyncMetadataStore.swift, SwiftDataSyncMetadataStore.swift, SyncEngine.swift)

Add applyLocalBookTombstone(_:mutation:) async throws, where mutation is a finite @Sendable async-throwing native canonical operation. A save failure before markTombstoneUngated returns is an ordinary error; a later mutation error is wrapped in typed SyncMetadataError.savedBookTombstone(BookID), recording the exact saved boundary without a fallible post-hoc query. Native implementation acquires bookIdentityGate once, calls markTombstoneUngated(.book), then awaits mutation. No indexing/network/drain inside. This is deliberately separate from withLiveBookIdentity, which correctly rejects tombstones.

Extend SyncEngine.markBookDeleted with optional finite canonical mutation (preserve its old wrapper). Enqueue/request sync whenever the tombstone has been saved, even when the later canonical mutation throws; do not lose the durable pending delete in that partial failure. Only native canonical mutation goes inside the identity gate, not metadata public methods or queue waits. Preserve acknowledged tombstone operation ID/dirty disposition rules.

### C. Native atomic conditional logical delete (BookStore.swift, SwiftDataBookStore.swift)

Add deletePermanentlyIfUnchanged(_:matching:accountPermit:) async throws -> Bool. Production SwiftData implementation performs owner/account-generation validation, expected canonical CAS, dependent-row removal and authorization tombstoning in one dbStore.write turn. Keep pending materialization. An absent canonical row with matching tombstoned owner remains idempotent. An owner/path/identity replacement fails rather than deleting another book. Do not use existing delete() (drops pending/auth) or unchanged deleteIfUnchanged() (drops auth). Keep protocol defaults only for compatibility fixtures; production binds the real atomic implementation.

### D. Library commit and deferred cleanup (LibraryViewModel.swift, LibraryViewModel+Make.swift, ServiceGraphFactory.swift)

Production factory beforeBookDeleted now captures immutable generation and synchronously returns retireBookForDeletion; no drain. Provide one optional combined logical commit callback taking Book+witness and returning a Sendable DeletionCommitOutcome: .committed(deferredCleanup:) or .savedNeedsReconciliation(reconcile:deferredCleanup:). The cleanup action is @Sendable () async -> Void; reconciliation is a finite @Sendable () async -> Bool action. Ordinary thrown errors mean the tombstone was not saved; the factory converts the typed savedBookTombstone failure into .savedNeedsReconciliation, preserving legacy callback behavior for compatibility. It captures prepareDeletionCleanup while canonical/pending provenance still exists, then calls the new SyncEngine tombstone+native conditional delete under original account admission. The callback returns its explicit saved outcome after finite persistence. Library completeDeletion treats BOTH outcomes as durable deletion: clear pending, retain closed projection suppression, never invoke rollback or failed-visible presentation, and refresh before reader close/physical cleanup. The partial outcome starts finite same-session canonical reconciliation before real drain; if persistence remains unavailable, log and retain durable closed intent for startup/retry rather than publishing the old Book. Its unstructured Task captures only the immutable book, close callback and returned action, never the VM or an entire view.

The returned cleanup/reconciliation action is assembled by the service graph factory (no new general coordinator/framework). The VM starts its simple unstructured Task after either saved outcome, awaits closePresentedReader, after any finite partial-save reconciliation, then the cleanup action awaits waitForRetiredBookDeletion(witness:) and executes the captured cleanup. Do not retain a broad owner-operation lease while waiting for old source/ARC drain, because account cleanup drains those leases. Re-admit a finite current-owner cleanup only when ready to mutate files; verify permanently closed old identity, canonical absence, exact old pending token and owner before touching the original namespaces. If authority/account ownership changed, leave physical artifacts for same-owner recovery rather than risking a replacement. Cleanup must not capture the VM/UI operation as a durable owner.

Capture closure must be retained until cleanup finishes; pending rows are removed by owner+token CAS only after physical cleanup succeeds. No plaintext file contents or titles in telemetry: logical_committed, cleanup_started, cleanup_finished/failed with Book/witness identifiers suffice.

### E. Restart reconciliation and cleanup (LibraryViewModel.swift, BookImportRecovery.swift, BookImportPersistence.swift, SwiftDataBookImportPersistence.swift)

Cross-store writes cannot be atomic. A crash after sync tombstone but before native deletion is closed by persistent projection filtering: snapshot Book candidates must query durable Book tombstones and omit them on every refresh, with existing owner/generation/publication fences around awaited reads. Production supplies the same real metadata store; empty optional provider remains compatibility only.

After a saved partial commit in the current session, and at account startup, reconcile durable tombstoned canonical rows under current immutable owner/account admission using the same native permanent conditional deletion. Then enumerate persisted pending materializations for this owner, including orphan ready jobs, and process only identities that are durably tombstoned AND canonical absent. Existing recovery iterates ownedBooks and therefore cannot clean missing-book orphan jobs; add an explicit bounded owner+token enumeration seam, never blanket-delete Imports directories. For each, capture/validate staging and old UUID namespace, fence/drain original source generation if present, perform repeatable cleanup, then owner+token CAS-remove pending. Metadata tombstones are never erased by cleanup. Limit this follow-up to affected imports with retained pending rows (including Kybalion ready jobs); do not add broad legacy Book-directory enumeration. Preserve retained authorization deny records permanently. Canonical absence alone is never proof that an arbitrary directory may be deleted.

### F. Same-file and remote path corrections (BookImporter.swift, SwiftDataBookImportPersistence.swift, ChangeApplier.swift)

Dedup reservation must skip orphan or durably closed same-hash pending candidates without removing their cleanup rows. Add excludedBookIDs: Set<BookID> to reserveRegistration (compatibility default empty); the importer supplies metadata-closed matching candidates/pending identities so a metadata-saved/native-not-yet-deleted contender is excluded immediately in the current session. Native reservation additionally checks tombstoned reading authorization when no canonical row exists and throws bookIDOccupied for an attempted deterministic closed UUID, before inserting any authorization; importer rotates to a fresh UUID. Never insert a second authorization for the same closed identity. Such rows are not pending import conflicts and cannot veto fresh UUID reservation. Deterministic old-ID candidates remain rejected by tombstone/native authorization; fall back to new UUID. Preserve typed deletionInProgress only while a precommit local witness has no saved tombstone; after commit reimport proceeds.

Actual remote tombstones must also fence synchronously while preserving/reusing any existing exact local deletion witness, perform finite canonical tombstone/ack under the native identity gate, then schedule physical drain/cleanup. Current applyBookTombstone precommit retireAndDrain callback would otherwise stall a sync wave when the local tombstone echoes, blocking the newly imported Book. Acknowledgement/canonical CAS protection remains; live replacement never uses deletion retirement.

## Failure and race checks for independent review

- Hold an idle reader VM/source lease forever: logical commit and new UUID import finish; physical old files stay until owner release.
- Hold genuine extraction/prediction/copy/audio effect: logical commit finishes; physical cleanup still waits the exact effect. Late old canonical/native writes cannot recreate row/auth.
- Cancellation/account switch before durable stage: no obsolete commit; rollback follows existing witness rules. Cancellation after saved tombstone cannot restore old ID or cancel committed deletion semantics.
- Crash between tombstone/native delete, and between native delete/cleanup: restart projection stays hidden, reconciliation closes auth/canonical, owner+token orphan cleaner resumes without recreating Book.
- Same SHA with old orphan pending and fresh reservation: new UUID succeeds; old deferred cleanup cannot touch new path.
- Remote echo while old owner held: finite ack/canonical deletion cannot wait old holder or block fresh Book sync.
- Repeated local/delete/recovery cleanup and generation replacement: UUID/witness/owner/token fences prevent old callback reopening/deleting replacement.
