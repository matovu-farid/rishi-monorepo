## Bug Summary
`prefsStore.test.ts` contains zero tests for `setVoiceChatVisionEnabled`
(prefsStore.ts:63-67) and `setTtsVisualCueEnabled` (prefsStore.ts:69-73).
Two production setter functions that persist user preferences and gate
reader/voice-chat features have no behavioral coverage. The
language-setter test (L46-52) pins the `invalidateKey()` side-effect to
exactly one call — but there is no symmetric negative test for the
other two setters, which deliberately do NOT call `invalidateKey()`.
A future refactor that "consistently" adds `invalidateKey()` to all
three setters (or removes it from all three) will not be caught.

## Tester Analysis
Production setters that ship in 1.3.31 and are wired to user UI
(settings panels) but untested:

```ts
// prefsStore.ts:63-67
async setVoiceChatVisionEnabled(enabled) {
  if (get().voiceChatVisionEnabled === enabled) return  // idempotency guard — UNTESTED
  await window.electron.setStoreValue('voiceChatVisionEnabled', enabled) // UNTESTED
  set({ voiceChatVisionEnabled: enabled })  // UNTESTED
}

// prefsStore.ts:69-73
async setTtsVisualCueEnabled(enabled) {
  if (get().ttsVisualCueEnabled === enabled) return     // idempotency guard — UNTESTED
  await window.electron.setStoreValue('ttsVisualCueEnabled', enabled)   // UNTESTED
  set({ ttsVisualCueEnabled: enabled })  // UNTESTED
}
```

Both deliberately omit `getVoiceChatService().invalidateKey()` —
unlike `setVoiceChatLanguage` (L59). That asymmetry is a contract
worth pinning: if a future contributor "uniformly" applies the
invalidation pattern to all setters, the voice-chat ephemeral key will
churn on every visual-cue toggle, which costs network round trips and
user-visible latency. Add three tests:

1. `setVoiceChatVisionEnabled(false)` persists via setStoreValue,
   updates state, does NOT call invalidateKey.
2. `setTtsVisualCueEnabled(false)` persists via setStoreValue,
   updates state, does NOT call invalidateKey.
3. Idempotency guard: calling either setter with the current value is
   a no-op (no setStoreValue, no state churn).
