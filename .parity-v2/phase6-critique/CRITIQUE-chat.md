# CRITIQUE — Chat & AI Experience (Mobile)

## Summary
Text-chat send path has data-integrity bugs around multi-conversation selection (always opens [0]) and a stale-history race in the RAG prompt. Voice-chat side is structurally solid but the agent ships with an empty activation context (no page text / outline / chapter), so on mobile the realtime agent has no idea which chapter the user is in — a key parity gap with electron. Several P1 polish issues around send-state, premium-gate timing, error UX, and missing thinking-sound parity.

## Notes
- Electron's `useChat.ts` includes a per-bookId cancellation token + `crypto.randomUUID` syncId backfill — mobile lacks both. The mobile flow uses an effect that doesn't cancel pending awaits on bookId change, so a fast back-and-forth between books can race conversation creation. (Lower-risk on mobile because `createConversation` is local-only, but worth tracking.)
- Mobile message persistence uses `addMessage` synchronously (SQLite); electron is async. Mobile already passes the result back into state, so optimistic ID logic isn't needed — but `sources` for the assistant message are only persisted via `addMessage(...., sources)` and never JSON-serialised through a schema validator. If the SourceChunk shape ever drifts, silent corruption is possible.
- The realtime tool `inspectCurrentPage` requires `react-native-view-shot` capture — page-capture.ts and the `RagExtractorHost` need a mounted root ref. If a user starts voice chat from a non-reader screen (or before the reader renders), the tool will reject. Worth a P2 if not already handled in `page-capture.ts`.
